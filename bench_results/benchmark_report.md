# Nano-vLLM 多级 KV Cache 性能对比报告

## 概述

本报告对比了三种 KV Cache 管理模式的性能：

1. **基线模式**：仅使用 GPU 显存
2. **两级缓存**：GPU + CPU 内存
3. **三级缓存**：GPU + CPU + SSD 磁盘

## 测试配置

| 参数 | 值 |
|------|-----|
| 层数 | 32 |
| KV 头数 | 32 |
| 头维度 | 128 |
| 块大小 | 256 tokens |
| GPU 显存 | 1.0 GB |
| CPU 内存 | 4.0 GB |
| SSD 空间 | 16.0 GB |
| 高水位线 | 85% |
| 低水位线 | 60% |

## 性能对比

### 各模式平均性能

| 模式 | Prefill (tok/s) | Decode (tok/s) | 显存峰值 (GB) | 换出次数 |
|------|-----------------|----------------|---------------|----------|
| 基线 (仅 GPU) | 3554 | 1422 | 0.63 | 0 |
| 两级 (GPU+CPU) | 4921 | 1950 | 0.63 | 9 |
| 三级 (GPU+CPU+SSD) | 4369 | 1687 | 0.63 | 27 |

| 并发数 | 基线 | 两级 | 三级 | 两级提升 | 三级提升 |
|--------|------|------|------|----------|----------|

| 4 | 1429 | 2000 | 1600 | +40.0% | +12.0% |

## 结论

### 主要发现

1. **两级缓存（GPU+CPU）**：
   - 显著提升高并发场景下的吞吐量
   - 减少 preempt 次数，提高服务稳定性
   - PCIe 传输开销较小，整体性能损失可控

2. **三级缓存（GPU+CPU+SSD）**：
   - 支持更大的 KV Cache 容量，适合超长上下文
   - 磁盘 I/O 开销较大，适合冷数据存储
   - 高并发下性能下降较明显

3. **适用场景建议**：
   - 低并发 + 短序列：基线模式足够
   - 中高并发 + 中等序列：两级缓存最佳
   - 超长上下文 + 低访问频率：三级缓存
